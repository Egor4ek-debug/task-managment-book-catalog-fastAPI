# Система управления книжным каталогом

## Проблемы хранения данных в оперативной памяти

Хранение данных в оперативной памяти (RAM) обеспечивает максимальную производительность операций чтения/записи, но имеет существенные недостатки:

1. **Волатильность данных**:
   - Все данные теряются при перезапуске или завершении работы приложения
   - Нет постоянного хранилища между сессиями
   - Не подходит для критически важных данных

2. **Ограниченный объем**:
   - Объем памяти ограничен ресурсами сервера
   - При большом количестве книг (тысячи/миллионы) приложение будет потреблять много памяти
   - Может привести к замедлению работы системы или аварийному завершению

3. **Проблемы масштабирования**:
   - Невозможно распределить нагрузку между несколькими серверами
   - Каждый экземпляр приложения имеет свою копию данных
   - Изменения на одном сервере не синхронизируются с другими

4. **Конкурентный доступ**:
   - При одновременном доступе нескольких пользователей возможны:
     - Race conditions (состояние гонки)
     - Потеря обновлений данных
     - Несогласованность данных
   - Пример: два пользователя одновременно пытаются обновить статус книги

5. **Отсутствие транзакций**:
   - Невозможно обеспечить атомарность операций
   - При сбое во время операции данные могут остаться в несогласованном состоянии
   - Нет механизмов отката изменений

6. **Безопасность**:
   - Данные уязвимы при атаках типа OOM (Out of Memory)
   - Нет встроенных механизмов резервного копирования
   - Сложно реализовать разграничение прав доступа
