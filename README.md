# Система управления книжным каталогом

## Проблемы хранения данных в оперативной памяти

Хранение данных в оперативной памяти (RAM) обеспечивает максимальную производительность операций чтения/записи, но имеет
существенные недостатки:

1. **Волатильность данных**:
    - Все данные теряются при перезапуске или завершении работы приложения
    - Нет постоянного хранилища между сессиями
    - Не подходит для критически важных данных

2. **Ограниченный объем**:
    - Объем памяти ограничен ресурсами сервера
    - При большом количестве книг (тысячи/миллионы) приложение будет потреблять много памяти
    - Может привести к замедлению работы системы или аварийному завершению

3. **Проблемы масштабирования**:
    - Невозможно распределить нагрузку между несколькими серверами
    - Каждый экземпляр приложения имеет свою копию данных
    - Изменения на одном сервере не синхронизируются с другими

4. **Конкурентный доступ**:
    - При одновременном доступе нескольких пользователей возможны:
        - Race conditions (состояние гонки)
        - Потеря обновлений данных
        - Несогласованность данных
    - Пример: два пользователя одновременно пытаются обновить статус книги

5. **Отсутствие транзакций**:
    - Невозможно обеспечить атомарность операций
    - При сбое во время операции данные могут остаться в несогласованном состоянии
    - Нет механизмов отката изменений

6. **Безопасность**:
    - Данные уязвимы при атаках типа OOM (Out of Memory)
    - Нет встроенных механизмов резервного копирования
    - Сложно реализовать разграничение прав доступа

## Сравнительный анализ способов хранения данных

В системе реализованы три подхода к хранению данных, каждый со своими преимуществами и ограничениями:

1. **Хранение в оперативной памяти**

```
books = []  # Временное хранилище данных
```

## Преимущества:

1. Максимальная скорость чтения/записи

2. Простота реализации

3. Идеально для прототипирования и тестирования

## Недостатки:

1. Данные теряются при перезапуске

2. Невозможно масштабировать

3. Ограничено памятью сервера

4. Риск потери данных при сбоях

Использование: Только для начальной разработки и тестирования

## 2. Хранение в JSON-файлах

```
class BookRepository:
    def __init__(self, file_path: str = "books.json"):```
```

## Преимущества:

1. Данные сохраняются между запусками

2. Человекочитаемый формат

3. Не требует дополнительного ПО

4. Низкая стоимость реализации

## Недостатки:

1. Низкая производительность при больших объемах

2. Проблемы с конкурентным доступом

3. Ограниченные возможности поиска

4. Нет транзакционности

5. Сложность масштабирования

Использование: Небольшие проекты (<10 000 записей), низкая нагрузка

## 3.Хранение в PostgreSQL

```
class BookRepositoryPostgres:
    def __init__(self, dsn: str):
```

## Преимущества:

1. Высокая производительность (индексы, оптимизация)

2. Поддержка транзакций (ACID)

3. Параллельная обработка запросов

4. Масштабируемость (репликация, шардинг)

5. Расширенные возможности запросов (SQL)

6. Надежное хранение больших объемов

## Недостатки:

1. Требует установки и настройки СУБД

2. Сложнее в реализации

3. Дополнительные ресурсы сервера

4. Необходимость миграций

Использование: Продакшен-среды, большие объемы данных, высокие нагрузки
